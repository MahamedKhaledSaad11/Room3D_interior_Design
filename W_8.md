# From Video to a Browsable 3D Room
*Cellula Technologies*

**Goal:** the user clicks an object in the 3D scene / or on random 2d frame where the object exist, the system finds that object in all frames, edits it consistently with a diffusion model, and rebuilds the 3D scene. A user-feedback fallback is allowed for tracking.

## 1. Week 2 Objective

Starting from the Week 1 system, add the following:

* The user clicks an object in the viewer and types an edit prompt (for example, `"make the sofa dark green leather"`). Note: the user can click on the 3D world, which is hard, or pick a frame from the UI where the UI will show the sampled frame at 1-4 fps and click on the object on the 2d frame which is much easier.
* The system finds the object in the frames, producing a mask per frame with SAM 3 or 2 or another segmentation model.
* A diffusion model edits the frames, conditioned on the mask, the prompt, and a reference edited frame. (Note: the flow is if we are editing the first frame, we just condition on the prompt and mask, then the second frame or later frames to enforce consistency of that same style design across the frames; we condition the first edited frame as a reference.)
  * Post-processing guarantees that nothing outside the mask changed.
* The splat is rebuilt from the edited frames and shown in the viewer.
* The project counts as done when the UI flow works: submit video, wait, inspect in free cam, click and edit, and view the result. The one hard part is automatic tracking of the object across frames. If that proves too hard, the fallback where the user marks the frames containing the object is fully acceptable.

## 4. Technical Guidance

### 4.1 Getting from a click to a target object 

* The user needs a starting point. Choose one, and document the choice.
* **Option 1 (recommended baseline): click on a reference frame.**
  * The viewer snaps to a training camera, and the user clicks on the object in that real image. This avoids 3D picking problems entirely.
* **Option 2: click in the 3D view.**
  * Cast a ray from the viewer's camera. Find the nearest point (or Gaussian) along the ray, then project that 3D point into the nearest training frame to get a 2D click.
* Then run the segmentation model on that frame with the click as a prompt, which gives the reference mask. Let the user add positive or negative clicks to refine it.

### 4.2 Tracking the object across frames

Implement the simplest method that works, evaluate it, and only then try to improve it. Methods, from the cheapest to the most ambitious:

1. **Video-style mask propagation.** Frames are already in temporal order, so use a video segmentation model (SAM 2, 3 style video predictor, or an older VOS model such as XMem or Cutie). Give it the reference mask and let it propagate forward and backward. Research which video segmentation models are available and fit in memory. This is the first thing to try. It fails when the camera leaves the object and comes back (the object is lost during occlusion or when it leaves the view).
2. **Neighbor-mask search.** Take the masks of frames $t-1$ and $t+1$ as prompts for frame $t$. Use the previous mask's bounding box or centroid as a box and point prompt for SAM, and check that the result overlaps the previous mask (IoU above a threshold). Re-initialize if overlap collapses.
3. **Lift to 3D and reproject (strong, uses your poses).** Take the reference mask and the depth for that frame (from VGGT depth or from the splat render).
   * Back-project the masked pixels into 3D points. This gives a small 3D point cloud of the object.
   * For every other frame, project those points with that frame's pose and intrinsics.
   * Do a visibility check against that frame's depth (if the point is behind another surface it is occluded, so ignore it).
   * The visible projected points become point or box prompts for SAM in that frame, and you can compare the resulting mask with the projected points for a sanity check.
   * This works across large viewpoint changes, where video propagation fails.

* **Camera FOV / frustum intersection (your idea).** Use this as a cheap filter and not as the main tracker. For each frame, check whether the 3D object points (method 3) fall inside the camera frustum. Frames that don't contain the object points are skipped, which saves compute and reduces false detections.
* **Feature-based re-identification.** Compute a feature descriptor (for example DINOv2 patch features) for the masked object in the reference frame. In other frames, find the SAM mask candidates whose features are most similar. Useful for re-finding the object after it leaves the view.
* **Splat-based masks (research option).** Select the Gaussians that belong to the object (for example, those whose projection falls inside the reference mask across several views), then render only those Gaussians' alpha in every camera to get a mask for each frame. Mention this in the report as future work unless there is time.
* **Fallback: the user marks the frames.** The UI shows a grid of thumbnails, and the user ticks every frame where the object clearly appears. SAM then runs on each ticked frame, prompted with the best available hint (the projected points from method 3, or a click the user places on that frame). This is guaranteed to work and is acceptable for the final demo.

### 4.3 Diffusion editing 

* **Model choices:** FLUX 3 Image Klein or Qwen-Image 2.1. First confirm from the model cards what each one supports (image editing, inpainting with a mask, multiple reference images), the license, the size, and the VRAM needed in bfloat16 or float8 or 4 on a T4 (any quantization).
* **Memory tools to research:** quantization, CPU offload, loading the text encoder, then freeing it before loading the transformer, and tiling the VAE.
* **Procedure:**
  * **First edited frame:** input = original frame, mask, prompt. Choose the frame where the object is large and clearly visible. Generate several seeds and let the user (or the team, for testing) pick the best one. This becomes the reference edit.
  * **Every other frame:** input = that frame, its own mask, the same prompt, and the reference edit as an extra conditioning image, so the style, color, and shape of the new object stay consistent.
* **Known problems to test and document:** the edit drifting in color, the model editing outside the mask, and the object changing shape between views.
* **Ideas to evaluate if time allows:**
  * Conditioning on both the reference edit and the previous edited frame (watch for error accumulation).
  * Tiling several frames into one image (a $2 \times 2$ grid) so the model edits them jointly.
  * Using the same seed and prompt for every frame.
  * Editing only keyframes and letting the 3D rebuild fill in the rest.

### 4.4 Rebuild the 3D scene 

* Do not re-run pose estimation. The camera poses and intrinsic stay the same. Replace the training images with the edited ones (for frames that were not edited, keep the originals) and either:
  * re-train the 3DGS from scratch (the naive version), or
  * start from the existing splat and fine-tune for a few thousand iterations (faster, to be tried as the first optimization).
* Compare the build time of both and report it.
* Keep the original splat so the viewer can switch between "before" and "after".

### 4.5 UI 

Required flow:

1. In the viewer, an "Edit object" mode: select a reference frame or click in the scene.
2. The mask preview appears. The user can add or remove points.
3. The user types the prompt and presses "Edit".
4. A tracking progress bar, then a grid of frames with the mask overlay. The user can remove wrong frames or mark the missing frames manually (the fallback).
5. A diffusion progress bar (frame $x$ of $N$) with a preview of the first edited frame so the user can accept it or regenerate with another seed before running the rest.
6. A rebuild progress bar, then the viewer with a before/after toggle. Keep it dead simple.
